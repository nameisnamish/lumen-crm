LUMEN CRM — BRANCH DIRECTORY & PHASE-ON-PHASE MERGE POLICY

BRANCH STRUCTURE:
----------------------------------------------------------------------
1. main (Production / Stable Release)
   - Status: Protected Production Branch.
   - Merge Policy: Merges happen ONLY at the completion of a major Project Phase / Milestone.
   - Commits: No direct commits. Only release merge commits and version tags (v1.0, v1.1, etc.).

2. develop (Active Daily Development)
   - Status: Primary Working Branch.
   - Merge Policy: All daily features, bugfixes, and refactors are committed here.
   - Workflow: Active branch for ongoing development.

3. feat/* and fix/* (Temporary Feature Branches)
   - Status: Short-lived task branches.
   - Workflow: Branch off develop -> Implement task -> Merge back into develop.


PHASE-ON-PHASE MERGE GATES (WHEN TO MERGE develop -> main):
----------------------------------------------------------------------
Never merge develop into main on routine daily changes. A merge to main is 
strictly authorized ONLY when ALL 4 Release Gates are satisfied:

[GATE 1] Phase Milestone Completion
   - All scheduled features for the target phase are 100% finished.
   - No half-finished UI or broken endpoints.

[GATE 2] Zero Build & Lint Errors
   - Frontend build passes with 0 errors (`npm run build`).
   - Backend boots cleanly with all route handlers intact.

[GATE 3] Smoke Test & Core Flow Verification
   - Dashboard KPIs & Adaptive Cadence (1M, 3M, 6M, 1Y, ALL) render accurately.
   - AI Copilot, Leads Kanban, and Contacts respond properly.

[GATE 4] Release Tagging & Changelog
   - Merge commit describes the complete Phase summary.
   - Git release tag created (e.g., git tag -a v1.0.0 -m "Phase 1: Core Dashboard & AI").
